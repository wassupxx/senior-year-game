Test Plan — «Еще один день в школе»

1. Цель тестирования

Проверить, что игровая логика и пользовательский интерфейс работают в соответствии с:

пользовательскими историями;

игровыми правилами;

критериями приёмки.

Основное внимание уделяется ресурсам игроков, событиям, управляемым действиям, очередности ходов, расчёту mentality_stability, условиям победы/поражения и отображению информации на экране.

────────

2. Объекты тестирования

2.1. Ресурсы игрока

У каждого игрока должны быть 5 ресурсов:

|Ресурс |Стартовое значение|
|-------|-----------------:|
|Стресс |5                 |
|Деньги |10                |
|Друзья |15                |
|Домашка|10                |
|Буллинг|0                 |

2.2. Показатель mentality_stability

Формула:

mentality_stability = money * 1.5 + friends * 1.5 - bulling - stress // 2

Показатель должен отображаться у каждого игрока и обновляться после каждого хода.

2.3. События

Перед каждым ходом игрока случайно выбирается одно из событий:

E1 — Обед

E2 — Контрольная

E3 — Прогул

E4 — Опоздание

E5 — Встреча с параллелью

E6 — Перемена

После выбора события random.random() < 0.5 определяет один из двух вариантов его эффекта.

2.4. Управляемые действия

Доступны 5 действий:

A1 — Сделать домашку с другом

A2 — Сбежать с последнего урока вместе

A3 — Списать у одноклассника

A4 — Рассказать слух

A5 — Подставить

После выбора действия игрок должен выбрать одну из 3 целей — других игроков.

2.5. Условия окончания игры

Победа:

1) игрок набрал 60 очков mentality_stability;
2) либо игрок остался последним, у кого буллинг не достиг порога поражения.

Поражение:

bullying >= 10.

После победы игра останавливается.
После выбытия игрок теряет возможность выполнять действия.

────────

3. Область тестирования

Входит в тестирование

1. отображение 5 ресурсов;
2. правильность стартовых значений;
3. обновление ресурсов после хода;
4. расчёт mentality_stability;
5. отображение текущего события;
6. корректность эффектов событий;
7. случайный выбор одного из двух вариантов события;
8. отображение последних 5 сообщений;
9. обновление лога;
10. отображение текущего игрока;
11. выбор действий;
12. отображение 5 действий после события;
13. блокировка действий при недостатке ресурсов;
14. выбор одной из 3 целей;
15. корректность изменения ресурсов у инициатора и цели;
16. условие победы;
17. условие поражения;
18. прекращение действий выбывшего игрока;
19. остановка игры после победы;
20. корректность отображения сообщений о победе и выбытии.

Не входит в тестирование

1. производительность игры при большой нагрузке;
2. сетевой режим;
3. сохранение/загрузка игры, если такая функциональность не предусмотрена;
4. совместимость с операционными системами, которые не используются командой;
5. графические элементы, не связанные с критериями приёмки.

────────

4. Типы тестирования

4.1. Функциональное тестирование

Проверка соответствия игровых механик заданным правилам.

4.2. Unit-тестирование

Автоматическая проверка отдельных функций игровой логики:

* расчёт mental_stability;
* проверка условий победы и поражения;
* применение эффектов событий;
* применение эффектов действий;
* изменение ресурсов.

4.3. Интеграционное тестирование

Проверка взаимодействия нескольких компонентов:

* событие → обновление ресурсов → обновление показателей;
* действие → выбор цели → изменение ресурсов двух игроков;
* изменение ресурсов → проверка победы/поражения;
* ход → обновление лога → переход к следующему игроку.

4.4. UI-тестирование

Ручная проверка элементов интерфейса:

* панель ресурсов;
* панель действий;
* выбор цели;
* сообщение о событии;
* лог;
* показатель mental_stability;
* сообщение о победе;
* сообщение о выбытии;
* индикатор текущего игрока.

4.5. Регрессионное тестирование

После исправления багов повторно проверяются исправленные функции и связанные с ними механики.

────────

9. Приоритеты тестирования

**Critical**

Ошибки, из-за которых игра не запускается или невозможно завершить игру:

* игра не запускается;
* игра зависает;
* невозможно сделать ход;
* невозможно завершить игру;
* не работает условие победы/поражения.

**High**

Ошибки, нарушающие основную игровую механику:

* неправильное изменение ресурсов;
* неправильный расчёт mentality_stability;
* неверные эффекты действий;
* неверные эффекты событий;
* игрок может продолжать играть после поражения;
* игра не останавливается после победы.

**Medium**

Ошибки интерфейса и отображения:

* неправильный лог;
* неверное отображение текущего игрока;
* неправильное отображение ресурсов;
* неверное отображение события.

**Low**

Незначительные визуальные ошибки, которые не мешают игре.

────────

10. Критерии начала тестирования

Тестирование начинается, когда:

* игра запускается;
* существует базовая игровая сцена;
* реализована базовая модель игрока;
* реализованы основные ресурсы;
* можно выполнить хотя бы один ход.

────────

11. Критерии завершения тестирования

Тестирование считается завершённым, когда:

* все Critical-баги исправлены;
* основные High-баги исправлены или согласованы с менеджером;
* все обязательные критерии приёмки проверены;
* unit-тесты игровой логики проходят;
* проведено регрессионное тестирование;
* финальная версия игры успешно проходит основной набор ручных тестов.

────────
